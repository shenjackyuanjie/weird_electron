# 第二轮代码审查与加固（2026-10-14）

基线：main `3dc88b0`（已合并的第一版及 Copilot 三条修复）。本轮仍只改 B 线本地算法、仿真、协议、实验与测试，不新增事故类型、云服务或 Agent。原计划 §2.2/§2.3 要求独立校验与真实执行，§7.3 要求按执行方案统计 SOC/功率/PCC/电压/关键负荷等约束。

## 发现和处理

| 问题 | 影响 | 处理 |
|---|---|---|
| 时长没有经过共享类型校验 | 字符串/数组/对象造成 TypeError；true 被当作 1 秒 | 严格数值 Duration；API、两种策略与 step 一致校验 |
| request_id 可任意字符串化，验证外层生成新 ID | 日志链断裂，非法 ID 被接受 | 有限长度非空字符串；继承方案 ID；冲突拒绝 |
| converged=true 可以缺少结果字段 | 安全检查会比较 None，不能稳定结构化失败 | 完整性校验，非法结果明确拒绝 |
| 并发重复接收可竞争 pending/回执 | 重复验证、覆盖待执行命令或观察到不一致状态 | 实例级 RLock；取消和回执查询 API；不声称分布式安全 |
| 回执缺少实际执行入口的独立复验证据 | 候选验证与实际执行验证无法在日志中区分 | 回执保存实际复验 ValidationResult |
| 旧执行越界统计遗漏 ESS 功率、电压、线路 | “零越界”统计覆盖面不足 | 用实际状态和回执独立审计；一个坏区间只计一次 |
| 所有 batch 不完整样本均退出 0 | 缺依赖/求解器故障会被当作一般不可行案例 | 分离 failure_kind；运行/审计失败返回 2，合理无解保留 |
| Windows 多个 Demo 共用一个多行步骤 | 检查不够独立，首个命令失败可能被后续命令掩盖 | 分为三个单命令 CI 步骤 |

## 验证方法

`tests/test_api_boundary.py` 在修改前：24 failed、10 passed；修复后全部通过。新增测试还覆盖四线程幂等接收、不同命令竞争、并发 step、取消/配置变更恢复、回执绑定、逐类观测越界、缺证据、无执行时 null 比率及命令行故障退出。

锁和指标算术的单元测试使用明确标注的人工 gate/数据，不冒充电气仿真。真实潮流仍由 integration 测试验证；额外的真实潮流用例给实际执行复验加一个纯元数据标记，检查日志保留的是第二次 gate，而不是第一次候选结果。

本地隔离环境：169 passed、25 skipped；跳过项全部需要真实 pandapower。`--require-ac` 在缺依赖环境中按预期退出 4，不能把本地结果称作完整验证。直接提交后由 GitHub Actions 在 Ubuntu/Python 3.11 和 Windows/Python 3.13 执行全部 194 项测试、三个独立 Demo、Schema 导出；Ubuntu 额外跑 40 seed × 两种策略实验。CI 使用 `--require-ac --strict-markers`，禁止用跳过替代真实 AC 测试，语句覆盖率门槛为 89%。以该提交对应的 Actions/JUnit/coverage 产物为最终验证证据。

## 未扩大的能力范围

模型仍为准稳态、两母线、单区间调度；完全孤岛与频率动态仍未实现。没有接入 MCP/IoTDA/AgentArts，没有将两种确定性策略包装成 Agent 对比。新增能量统计只覆盖实际执行的时间区间，失败后的能量不外推。并发锁只保护单实例单进程；认证、设备授权、跨进程幂等、持久化和真实设备保护仍须后续实现。
